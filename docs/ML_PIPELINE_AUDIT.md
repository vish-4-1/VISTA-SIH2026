# VISTA ML Pipeline Audit

## Executive result

The ML code now fails closed rather than presenting synthetic or out-of-domain results as operational predictions. No checked-in root model artifact is eligible for inference: its metadata lacks the required `validated_for_inference: true` and `feature_schema_version: vista-flow-v1` declaration. The existing serialized models and historical metric/SHAP files were not replaced or deleted.

The VISTA training data is generated by `DATASET/DS_GEN_V2.py`; its application and attack labels select the profiles from which packet/timing features are generated. These datasets are useful for development and regression tests, not independent real-world validation. The archived ISCXVPN2016 data contains application/VPN labels, but its consolidated labeled CSV has no capture/session identifier and its per-capture CSVs have `No Label` in every row. It cannot presently support defensible group-held-out training on the live VISTA schema. The StrongSwan benign-workload model remains a non-approved candidate; no root model was replaced or approved.

The checked-in StrongSwan PCAP was reprocessed after the inference-boundary changes. Its 12 packets remain observable as an 8-packet ESP flow and a 4-packet IKE flow. Both flows are explicitly out-of-distribution for the available ML models, and no traffic, attack, or anomaly label is emitted. This is the correct result for the current model/data boundary; it is not a successful ML classification.

The earlier 28/8/50 evaluation is not accepted as a clean outer-ESP experiment: its training sources mixed cleartext ICMP/TCP packet captures with ESP captures, while the held-out run contained ESP only. Its saved predictions do reproduce the reported metrics, but the capture-plane mismatch invalidates the claim as an ESP-only generalization test. The historical report/model were preserved.

The corrected candidate's saved Random Forest and probability outputs reproduce, and its metrics recompute to 1.0 on 50 held-out packet-table rows. This score is not session-independent evidence. The source has processing-run IDs but no independently verified capture-session IDs: train and validation are both drawn from processing run `20261005T155313Z`, while the 50-record test comes from one other processing run, `20261005T155356Z`. Thus validation shares a run with training and the test represents one held-out run, not 50 independent sessions. Per-observation raw PCAPs and independent endpoint ground-truth sidecars are not present in these source directories; the label parquet has explicit ICMP/TCP labels, but the label origin is not independently established.

The shortcut audit found more than the known packet-count shortcut. Fourteen of 18 individual `vista-flow-v1` features, including packet count, byte count, flow duration, packet-size statistics, IAT statistics, directional counts/bytes, and direction ratio, each classify all 50 test records correctly when used alone. A depth-1 decision tree also scores 1.0. Removing packet count, any one feature, or the tested feature groups leaves the Random Forest at 1.0. This reflects several correlated fixed-recipe signals, not robust behavior learning. The majority-class baseline gets 0.50 accuracy and 0.333 macro-F1. Experiment IDs and packet-table filenames themselves reveal the target class, although they were excluded from model inputs; exact duplicate feature rows occur twice within the held-out set, but no exact vectors or packet-table hashes cross splits. No near-duplicate pair met the defined `1e-6` relative feature tolerance. These findings and all ablations are in the versioned audit report.

Accordingly, the perfect score is reproducible on saved artifacts but does not support generalization beyond the fixed recipes. The candidate remains blocked from inference: the backend excludes ESP/IKE, the task is not application/attack classification, and no session-level validation or independent per-observation ground-truth record is available. The corrected batch extractor matches backend `vista-flow-v1` flow features on tested IPv4 packet fixtures only.

The checked-in collection pipeline now validates versioned manifests, source hashes, explicit JSON ground-truth records, negotiated-SA evidence references, IPv4 packet tables, and per-session splits. It is tested offline with non-operational fixtures. There is no complete source manifest for the historical StrongSwan packet tables, so those records cannot pass the pipeline's provenance/readiness gate. The data-collection protocol documents the real ICMPv4 path and the missing configurable ICMP/TCP endpoint work; fixed synthetic summaries for other workload categories are excluded.

A separate historical DH-group ML report claims that 60 handshakes, including 20 ECP-256, were successfully negotiated. That claim conflicts with the independent StrongSwan capability report, which marks ECP-256 blocked. Raw handshake captures alone do not prove the negotiated group, and per-sample SA evidence is unavailable to resolve the contradiction. Accordingly, the DH-classifier data/metrics are **not accepted as verified evidence**.

### Runtime feature comparison

Both paths aggregate the complete analyzed capture by protocol-family and canonical bidirectional endpoints; there is no idle timeout. Forward is the lexicographically first `(IP, port)` endpoint, backward is the reverse. Candidate packet tables are IPv4 native-ESP captures with zero ports; IPv6 packet-length handling is not covered. Backend `ModelService` rejects missing/non-finite mandatory model values instead of imputing them.

| Feature (runtime order) | Units and definition | Batch-to-runtime finding |
|---|---|---|
| `packet_count` | packets; count within bidirectional flow | Match |
| `byte_count` | bytes; sum IPv4 IP lengths, excluding link framing | Match |
| `flow_duration` | seconds; last minus first timestamp, rounded to 4 decimals | Matched; extractor now rounds identically |
| `mean_packet_size` | bytes; mean IP length, rounded to 1 decimal | Matched |
| `std_packet_size` | bytes; population standard deviation (`ddof=0`), rounded to 1 decimal | Fixed; earlier batch used pandas sample deviation |
| `min_packet_size`, `max_packet_size` | bytes; extrema of IP length | Match |
| `mean_inter_arrival_time` | seconds; mean of sorted adjacent timestamp deltas, rounded to 5 decimals | Fixed; earlier batch filled zero when no precomputed IAT column existed |
| `std_inter_arrival_time` | seconds; population deviation of sorted timestamp deltas, rounded to 5 decimals | Fixed; earlier batch used sample deviation or zero |
| `min_inter_arrival_time`, `max_inter_arrival_time` | seconds; extrema of adjacent timestamp deltas, rounded to 5 decimals | Fixed; earlier batch used zero without an IAT column |
| `packets_per_second` | packets/second; packet count / rounded duration | Match; undefined for zero duration |
| `bytes_per_second` | bytes/second; byte count / rounded duration | Match; undefined for zero duration |
| `forward_packet_count`, `backward_packet_count` | packets by canonical endpoint direction | Match on tested IPv4 tuple |
| `forward_bytes`, `backward_bytes` | bytes; direction-specific sum of IP lengths | Fixed; earlier batch approximated using global mean size × direction packet count |
| `direction_ratio` | ratio; forward packet count / total packet count, rounded to 3 decimals | Match; backend descriptor corrected from misleading “byte ratio” wording |

Missing timestamps/lengths are now rejected by the batch extractor; single-packet IAT and zero-duration rates remain undefined and become insufficient data for inference. This feature arithmetic agreement is limited to IPv4 and does not override the backend's explicit ESP/IKE out-of-distribution policy.

## Model, evaluation, and explanation status

### Model artifacts and task separation

- Existing root model bundles are retained for inventory/compatibility, but are not inference-approved. Their metadata does not establish the current feature schema and validation eligibility.
- Traffic classification, attack classification, and anomaly scoring remain separate tasks. The attack task no longer falls back to the unrelated XGBoost traffic classifier. Traffic-classification results no longer imply `isAttack`.
- ESP and IKE are not treated as application or attack flows. They are retained as observed protocol evidence and returned as out-of-distribution for all three ML tasks.
- Anomaly predictions require validated schema/model metadata and an independently justified threshold. The anomaly training script no longer computes a q90 threshold on the same training-normal records or publishes such a result as performance.
- The legacy root-model metrics are not accepted as production performance evidence. They are associated with synthetic/generated labels, and the old aggregate metric files do not carry sufficient model/schema/held-out provenance. The API withholds them rather than relabeling or recomputing them. The narrower StrongSwan experiment reports are retained as scoped laboratory evidence only.

### Leakage-safe evaluation and artifact safety

- Added a group-disjoint train/validation/test split with overlap checks, group-missing checks, row-ID rejection, and a minimum group count. A focused unit test exercises group isolation.
- The ISCX experiment requires a source-provided `--group-column`, checks class presence in all three splits, selects candidates on validation data, and evaluates only the selected candidate on the held-out test set.
- The current consolidated ISCX dataset does not contain such a column. The runner exits with a diagnostic before creating models or reports.
- The baseline, XGBoost, traffic, attack, anomaly, and ISCX training scripts write to unique `models/candidates/...` and `reports/candidates/...` locations; they do not replace existing root models or shared metrics.
- Candidate metadata explicitly keeps `validated_for_inference` false. Public ISCX feature bundles additionally identify their incompatible source schema.
- The benign evaluator now reads the saved packet tables, recomputes features under `vista-flow-v1`, hashes every capture, rejects non-finite features and verifies group/feature-vector separation. Its held-out metrics are calculated after reloading the saved predictions CSV.

### SHAP, API, and dashboard

- Global SHAP artifacts are returned by the API only when evaluation/model/schema provenance qualifies. The existing top-features file lacks that provenance and is withheld.
- `run_shap.py` no longer trains on the full dataset when an artifact is absent. It requires an inference-approved model, exact `vista-flow-v1` metadata, and a matching SHA-256 for the held-out test dataset.
- Per-flow SHAP accepts exactly one selected feature row and verifies fitted feature order. Its contract is unit-tested; no current production model is eligible to produce operational explanations.
- PCAP analyses have unique analysis IDs and per-analysis flow IDs. ESP/IKE and unsupported predictions preserve observed metadata while keeping labels/probabilities null. CSV analysis also gets isolated IDs; report requests reject conflicting analysis IDs.
- Dashboard copy distinguishes synthetic development data and unsupported/unvalidated model states from verified outcomes.

## Changes made in this audit

- Removed synthetic fallback behavior between the independent inference tasks, added explicit model/schema eligibility checks, and separated Isolation Forest semantics.
- Marked ESP/IKE as out-of-domain for current traffic/attack/anomaly models while preserving their packet observations.
- Added group-disjoint three-way split validation and regression tests.
- Removed fabricated capture/session metadata from the ISCX adapter.
- Reworked the ISCX experiment runner so it requires real source group IDs, selects on validation data, writes candidates only, and refuses the currently available ungrouped dataset.
- Corrected batch flow extraction (real timestamp IATs, population standard deviations, exact per-direction byte sums, runtime rounding and strict missing-data handling) and added an explicit ordered runtime feature contract.
- Re-evaluated the benign candidate on ESP-only train/validation captures and a separate ESP-only held-out run; historical mixed-protocol-plane candidate evidence was retained but superseded.
- Reproduced the candidate and added packet-count, majority, depth-1 tree, single-feature, individual-feature-removal, and feature-group ablation evidence. The audit surfaced shared train/validation processing-run provenance, label-coded IDs, and two duplicate test feature rows.
- Added a manifest-driven offline dataset validator/preparer, experiment manifest schema, collection matrix, and data-collection protocol. It refuses row-level split fallback and quarantines missing or inconsistent provenance.
- Redirected training scripts to unique candidate locations; removed same-training-set anomaly-threshold reporting.
- Changed the SHAP CLI to require approved model provenance and a hash-matched held-out dataset, with no train-on-full-data fallback.
- Updated API/UI expectations and SIH requirement documentation to avoid treating synthetic or unqualified outputs as verified.

No dataset, production model artifact, VPN configuration, StrongSwan container, or Docker topology was changed by this phase. A candidate-only model was retrained and stored under a unique versioned path; no production artifact was changed or approved.
